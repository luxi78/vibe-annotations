# Troubleshooting

## Offline service or missing MCP tools

Run pinvelto status, then pinvelto start --daemon if stopped. Read pinvelto logs --lines 50. Verify http://127.0.0.1:3847/mcp, reconnect the agent, and request its tool list. The server must identify itself as pinvelto and expose the seven pinvelto_ tools.

## Endpoint occupied or ownership mismatch

A generic healthy response or another product is not Pinvelto. The CLI refuses to stop an unowned service, including a stale PID record. Inspect the reported owner rather than killing a PID. Isolated automation can select PINVELTO_PORT and PINVELTO_HOME; the production extension expects 3847.

## Extension or capture unavailable

Load production .output/chrome-mv3, enable the extension, and reload target pages. Check site access and capture permissions. Restricted browser-owned pages cannot be injected. Use the extension action to enable supported sites; keyboard shortcuts may differ by browser.

## Installation or update failure

Use Node 24, pnpm 11, the reviewed revision, and frozen lockfile. Install the local packages/server directory. Use a writable prefix if needed; Windows can use pinvelto.cmd when script policy blocks the wrapper. Stop a linked service before switching revisions, rebuild, and reload the matching extension.

## Missing images or import rejected

JSON and Markdown do not bundle image bytes. Keep original files or attach them again. HTML embeds available images through the service and omits unavailable files. Inspect the review before sharing it. Legacy upstream import is unsupported; new Pinvelto exports carry their own identity.
